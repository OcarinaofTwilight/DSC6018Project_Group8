# melanoma_calib

**Class-balanced losses do not buy sensitivity** — a calibration-first, patient-disjoint
benchmark on ISIC 2020.

> Plain BCE beats inverse-prevalence and focal loss on sensitivity at 80% specificity, on
> ranking *and* on calibration. The two balanced objectives fail calibration in opposite
> directions, and only focal loss is repairable by a single temperature. Every number in this
> repository is recomputable on a CPU.

SDSC 6018 final project · Group 8 · Ke Liu, Zeyu Fu, Dong Wang, Kai Liu
(Department of Data Science, City University of Hong Kong)

## Results at a glance

Held-out test set: 6,625 images / 117 melanomas / 411 patients. The operating threshold is
frozen on validation and applied unchanged; brackets are 95% patient-level bootstrap intervals.

| Model | AUROC | AUPRC | ECE | Calibration slope | Sens@Spec80 |
|---|---|---|---|---|---|
| **B3 + BCE** | **0.892** [.865,.917] | 0.140 [.101,.202] | **0.0045** | 0.80 | **0.803** [.720,.884] |
| B3 + inv-prev BCE | 0.860 | 0.091 | 0.0339 | 0.43 | 0.726 |
| B3 + focal | 0.876 | 0.169 | 0.1355 | 1.85 | 0.812 |
| R50 + BCE | 0.855 | 0.104 | 0.0055 | 0.65 | 0.761 |
| B3 + BCE + metadata | 0.889 | **0.218** | 0.0059 | 0.79 | 0.752 |

In one sentence: **balancing bought neither sensitivity nor calibration.** Inverse-prevalence
BCE is over-confident and structurally miscalibrated; focal loss is under-confident but a
single temperature repairs most of it. See `results/results.md` and the report for detail.

## Recompute every table and figure without training (CPU only)

This is the fastest way for a teammate to re-test the results — `runs/` already holds the
per-image predictions:

```bash
python src/report.py --runs "runs/*" --out results/          # main table + paired contrasts
python src/figures.py --preds "runs/*/test_preds.csv" --out-dir figures/
python tools/bootstrap_frozen.py                             # paired CIs with a frozen threshold
python tools/make_report_assets.py                           # the four report figures
```

**Note:** `src/report.py` re-estimates the threshold inside every resample, which is slightly
optimistic. The report uses `tools/bootstrap_frozen.py` (threshold frozen once). The difference
between the two protocols is discussed in report §4.3 and in the appendix.

## Full reproduction (needs ≥6 GB of VRAM)

```bash
# 1) Data: Kaggle account -> Settings -> Create New Token, save the token as secrets/kaggle_token
python tools/kaggle_download.py --list                       # check the dataset is visible first
python tools/kaggle_download.py --out data/train             # resumable
python tools/inspect_data.py --csv data/train.csv --img-dir data/train   # eight-point health check
python tools/resize_images.py --src data/train --dst data/train_256      # 1024 -> 256, rerunnable

# 2) Freeze the split (optional; you can reuse manifests/split_seed42.csv)
python src/split.py --csv data/train.csv --out manifests/split_seed42.csv --seed 42

# 3) Smoke test (2 minutes: paths / VRAM / weight download)
python src/train.py --manifest manifests/split_seed42.csv --img-dir data/train_256 \
    --epochs 1 --limit-batches 5 --out-dir runs/_smoke

# 4) Five training runs (one RTX 2060 Max-Q, ~3.4 GPU-hours in total)
python src/train.py --manifest manifests/split_seed42.csv --img-dir data/train_256 \
    --model efficientnet_b3 --loss bce   --epochs 12 --batch-size 16 --out-dir runs/b3_bce
python src/train.py ... --loss wbce  --out-dir runs/b3_wbce
python src/train.py ... --loss focal --out-dir runs/b3_focal
python src/train.py ... --model resnet50 --out-dir runs/r50_bce
python src/train.py ... --meta      --out-dir runs/b3_bce_meta

# 5) Evaluation + temperature scaling (four-way flip TTA)
python src/evaluate.py --manifest manifests/split_seed42.csv --img-dir data/train_256 \
    --ckpt runs/b3_bce/best.pt --split test --out runs/b3_bce/test_preds.csv
python tools/fit_temperature.py --run-dir runs/b3_bce

# 6) Aggregate and plot
python src/report.py --runs "runs/*" --out results/
python src/figures.py --preds "runs/*/test_preds.csv" --out-dir figures/
```

On Windows you can also use the one-command scripts in `scripts/`
(`setup.ps1 → data.ps1 → train.ps1 → eval.ps1 → report.ps1`). They locate everything
relative to the cloned repository, with `data/`, `runs/`, `results/` living beside it
(see `scripts/_common.ps1`), so moving the repo to another folder is enough — nothing is
cached under `C:`.

## Design notes (why it is written this way)

| Decision | Reason |
|---|---|
| Patient-level split, frozen with SHA-256 | Multiple images per patient are near-duplicates; image-level splitting inflates AUROC by 3–8 points |
| Splitter = greedy + swap-repair | Greedy alone drifts badly on heavy-tailed patient sizes (measured: test prevalence 1.76% → 0.56%) |
| Threshold chosen on validation only, then frozen | Searching for 80% specificity on test and then reporting sensitivity is tuning on test |
| Three calibration views + slope | At 1.76% prevalence the whole-sample ECE is dominated by benign images; a constant predictor also scores below 0.01 |
| Patient-level **paired** bootstrap | Image-level resampling under-covers; comparing two independent CIs under-states the difference |
| Temperature scaling as the operational H3 | Monotone, so AUROC/sensitivity cannot move — which makes it a clean test of "scale vs structure" |
| Metadata restricted to age / sex / site | `diagnosis` and `tbp_lv_*` are label-derived or unavailable clinically; using them is leakage |

## Environment

Python 3.10.8 · PyTorch 2.6.0+cu124 · timm 1.0.9 · one RTX 2060 Max-Q (6 GB).
Five training runs took 3.4 GPU-hours in total; all aggregation and plotting runs on CPU.

`timm 1.0.9` imports `huggingface_hub.repo_type_and_id_from_hf_id`, a symbol removed in
hf_hub 2.x. `src/hf_compat.py` restores it before `import timm`, so both 0.2x and 2.x work with
no downgrade.

## Known limitations

A single split and a single seed (the intervals contain sampling noise, not run-to-run
variance); 256 px only; no Grad-CAM; the effective-number weighting condition is implemented
but was never trained (the compute went to the metadata ablation). All of this is stated in
report §8.

## Pushing to GitHub

The repository is already in a pushable shape (no `.venv`, no data, no weights, no credentials).

```bash
cd melanoma_calib_github
git init -b main
git add .
git status                      # confirm there is no data/, runs/**/*.pt or secrets/
git commit -m "ISIC 2020 calibration-first benchmark: code, frozen split, predictions"
git remote add origin git@github.com:<org>/<repo>.git
git push -u origin main
```

Two reminders:

* **Do not enable Git LFS.** `runs/**/*.pt` is already excluded by `.gitignore`; keep the
  weights (43–94 MB) in a Release or on a cloud drive rather than in history.
* If a teammate clones this on Windows and runs `scripts/*.ps1`, the first step is
  `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1` to create the venv.

`docs/` holds the two report PDFs this repository produced (English and Chinese), so that
someone joining can read the conclusions before reading the code.
